ROI 的计算口径与为什么不追所有高级技术

优先级参考 = R × B × S × T × A ÷ H

R=相关岗位需求强度；B=形成技术壁垒；S=薪资潜力；T=迁移性；A=实习前形成可信证据的可达性；H=达到本计划验收的增量小时。JD 样本只约束 R，不能提供真实薪资或录用概率。S 因缺数据统一取 1，保持中性；其余为规划者 1–5 主观评分。分数用于取舍，不是测量结果；必需前置与求职任务优先于公式排序。

所有性能实验通用验收协议
层次必须固定 / 记录验收和误用防线
环境GPU 型号/数量/显存、PCIe/NVLink、功耗/时钟策略、driver/runtime、OS、库版本、tag+完整 SHA、model revision、dtype、量化与 tokenizer/template开始/结束均保存；共享机器注明干扰；硬件变化不能直接归因优化。
Kernel先正确性；空/边界/非整倍/随机；明确 atol/rtol；warmup≥20；≥100 次 Event×3 批次；相同 stream 同步完成排除编译、内存分配、下载；分别报告 kernel-only 和必要时 E2E。每个算子至少一份代表性 profile，profiler 时间不用于报告性能。
Serving固定 seed/数据集/hash、实际 token 长度、到达模式、并发或到达率、engine 参数、cache 冷热；先 10 请求热身；每配置≥50 成功请求×3 轮失败/拒绝/超时单列，不能删掉；少样本 p95 仅探索性。重要结论扩到≥200 请求/轮（资源允许）；对同条件交错 A/B 降低热漂移。
通信nccl-tests commit、NCCL runtime、dtype、消息大小、ranks/GPU 数、拓扑、transport、warmup/iters、校验微基准 bandwidth 不能代表应用加速；algbw/busbw 区别写清；单卡 -g 1 不是多卡通信。

主项目控制轴：先 C={1,4,8} × input={128,1024} × output=64 的 6 组；再逐轴加 output=256、batch/token budget、prefix 冷热、chunked prefill、KV memory 配置；双卡才加 TP=2。避免 8 个开关全因子组合。新变量每次最多一个；OOM/不支持也是结果。

指标口径：TTFT=t_first−t_submit（包含客户端观察到的排队/传输）；E2E=t_last−t_submit；TPOT=(t_last−t_first)/(N_out−1)，N_out≤1 记 NA；ITL 是相邻 token 时间间隔，不等同 TPOT 分布。若流式 chunk 包含多 token，要说明 token 时间精度，不能把 chunk 间隔冒充逐 token ITL。output tokens/s=成功输出 token 总数÷统一测量窗口；总 token 吞吐另外命名。报告 p50/p95、请求数、失败数及轮间波动。

服务计时用单调墙钟；CUDA Event 用于 GPU kernel，不拿 Event 代替端到端服务计时。allocated/reserved、KV 预算、nvidia-smi device used 分别记录。GPU utilization 只是线索，不能单独判定 compute-bound。

模型与 KV Cache 的手算模板

权重字节 ≈ 参数量 × 每参数字节数
普通 dense MHA/GQA/MQA 的 KV 字节 = 2 × L × ΣSᵢ × H_KV × D_head × bytes_per_element

纯演算例（不是 Qwen 的真实配置）：8B 参数 BF16 权重约 16×10⁹ B≈14.90 GiB；L=32、H_KV=8、D_head=128、B=1、S=8192、BF16 时，KV=1,073,741,824 B=1 GiB。若等长 B=4，KV 为 4 GiB；GQA/MQA 相比同 Q 头数的 MHA 减少 H_KV，因而减少 KV。

实际还要加 activation、workspace、CUDA Graph、allocator 与碎片；低比特还含 scale/metadata。TP 不能盲目按卡数平均除 KV（KV 头复制/分片约束）；MLA、hybrid/滑窗模型需换公式。因此主实验先选小型 dense Qwen3-0.6B，下载其真实 config 再算。

Prefill 能把大量 token 组成矩阵运算，通常更容易提高计算利用率；小 batch decode 每步只生成少量 token，权重和 KV 读取摊薄不足，常受访存带宽限制。高 batch/长上下文/不同后端可改变瓶颈，最终用 profile 验证，不背绝对结论。

固定求职节奏

10 月：岗位库、资格核对、简历 v1。
12 月：项目 v0.1，能满足条件的日常实习开始试投。
1 月：主项目 v1、模拟面试，首批 3–5 个合资格岗位。
