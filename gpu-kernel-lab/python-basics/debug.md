# 2026-10-09 越界错误调试记录

## 失败复现

- 工作目录：项目根目录。
- 运行环境：本机 `Python 3.14.4`（助手在本次记录时核对）。
- 命令：`python3 gpu-kernel-lab/python-basics/index_debug.py`
- 输入：脚本内列表 `latencies_ms = [8, 12, 10]`，循环上界为 `len(latencies_ms) + 1`。
- 运行前预测：本人预测 `index == 3` 时会报错；列表长度为 3，合法索引只有 0、1、2。
- 实际结果：本人终端依次输出 `0 8`、`1 12`、`2 10`，随后在 `index_debug.py` 第 4 行的 `latencies_ms[index]` 处出现 `IndexError: list index out of range`。该输出来自本人提供的终端截图；助手在修复前检查了磁盘脚本与截图所示代码一致。
- 此阶段只复现失败，下面继续记录断点定位与修复。

## 断点定位

- 本人在项目根目录运行 `python3 -m pdb gpu-kernel-lab/python-basics/index_debug.py`，在第 4 行设置条件断点 `b 4, index == 3` 并继续运行。
- 断点处实际查看到：`index` 为 `3`，`len(latencies_ms)` 为 `3`，`latencies_ms` 为 `[8, 12, 10]`；终端截图显示了这三项及断点位置。
- 本人解释：`range(4)` 产生 0、1、2、3，而长度为 3 的列表只有索引 0、1、2。读到索引 3 时没有对应元素，因此越界。

## 修复与复测

- 本人把循环范围从 `range(len(latencies_ms) + 1)` 改为 `range(len(latencies_ms))`，使索引只取 0、1、2。
- 独立预期：脚本依次输出 `0 8`、`1 12`、`2 10`，无 traceback，退出码为 0。预期来自列表内容和索引范围，而非复制运行结果。
- 实际结果：本人从项目根目录运行原命令，终端依次输出上述三行，`echo $?` 输出 `0`；助手随后复跑脚本，得到相同三行并正常退出。
- 结论：此次越界由循环上界多加 1 导致；改成列表长度后，`range` 不会产生非法索引 3。此结论针对当前列表遍历练习。
