## 实施约定（教学补充，不是路线图原文）

- 使用 C++17 与标准库，CPU 即可。助手只读核对 g++ 15.2.0、Python 3.14.4 可用；本人已保存并运行助手提供的最小普通排序示例，编译器版本仍来自助手环境核对，不从截图推断本人终端版本。
- 代码位置：`gpu-kernel-lab/cpp-basics/stl_stats.cpp`。本日单独定义请求结构体，字段为 id、model、latency_ms，不改旧的 request.hpp。
- 请求编号为测试内唯一字符串，模型为非空字符串，延迟为有限非负毫秒数；先使用代码内构造的输入，不增加文件解析主题。
- 排序按延迟升序；仅比较延迟时，同延迟项不要求原顺序，测试核对非递减及所有原请求恰好保留。
- 分组按 model 精确匹配；每条请求只进入对应模型一组，出现次数及字段保持。unordered_map 的组间遍历顺序不作为验收条件。
- 排序和分组是两个操作；本次采用独立操作，分组函数按传入请求的原遍历顺序添加，未先排序。组内顺序按输入顺序核对，组间遍历顺序不作要求。
- 排序三类：普通乱序（延迟 30、10、20 → 10、20、30）、边界（空与单元素）、相同延迟（只要求非递减且请求不丢失）。
- 分组三类：多模型交错（A、B、A → A 两条/B 一条）、空输入（零组）、全部同模型（仅一组且全量保留）。各组具体 id 和字段在运行前保存 expected。
- 分组本轮预存输入与 expected：mixed 输入 r1/A/30、r2/B/10、r3/A/20，期望 requests=3、groups=2，A 按顺序含 r1/30、r3/20，B 含 r2/10；empty 输入空，期望 requests=0、groups=0；same_model 输入 r7/A/8、r8/A/3，期望 requests=2、groups=1，A 按顺序含 r7/8、r8/3。模型全名使用 model-A/model-B；组间输出顺序任意，所有请求完整字段必须保持。
- 迭代器：先理解其表示元素位置，再由本人解释至少一个具体失效场景及安全处理方式；不执行失效后的访问来充当验收。
- 固定项安排：旧异位词题的大小写不敏感变式，输入仅 A–Z/a–z，比较忽略大小写；保留代码、复杂度和边界。属于原定周四变式的实施选择，不另计新题。
- P1 补充验收：本人给出一组具体反例或一条限制，解释它影响什么结论、何时仍适用；可围绕“全局延迟排序是否就完成模型分组”讨论，后续先收本人判断。
- 建议时间：P0 主任务约 100 分钟，固定项 20 分钟已包含在 P0 120 分钟内；P1 30 分钟，全日 150 分钟。实际时长待本人报告。
