# LLM 推理性能实验

这个目录用于研究：**一个大语言模型在 GPU 上提供服务时，时间花在哪里？改变一个条件后，结果为什么会变化？** 最终目标是用真实测量和运行记录，解释单卡推理服务的性能，并验证至少一个可以被数据推翻的改进假设。

现在不用先掌握推理引擎的全部细节。项目会从能重复运行的基线实验开始，再逐步阅读代码、定位瓶颈、提出假设并复测。一次修改没有提升，也属于需要如实记录的结果。

## 要做什么

1. **建立基线：**固定模型、软件版本和测试请求，记录原始结果。例如请求多久开始返回、整个请求用时多久、每秒输出多少 token，以及显存占用。这里的 *token* 是模型处理文本时使用的单位。
2. **查找原因：**结合运行日志、性能分析记录和推理引擎源码，找出值得验证的瓶颈。日志显示的现象与原因要分开写。
3. **一次只改一个主要条件：**例如请求并发数或某项引擎配置，然后在相同条件下重复测试。保存原始数据、失败结果和结论的适用范围。

预期会学习和使用 vLLM、SGLang 等推理引擎。具体模型、版本和测试参数应在开始实验时确定并记录，不由这份说明预先宣称已经验证。

## 文件放在哪里

| 路径 | 用途 |
| --- | --- |
| `configs/` | 保存实验配置、版本与硬件信息。`hardware.json` 是本机硬件快照，只在本地保存；正式实验还需核对当时环境。 |
| `workloads/` | 保存测试请求及其输入长度、输出长度、并发等设置，让不同运行使用可比较的负载。 |
| `src/` | 保存调用推理服务、处理请求或实施实验改动的代码。 |
| `bench/` | 保存运行测试的脚本、命令和计时方法。 |
| `results/raw/` | 保存每次实验的原始输出，例如逐请求记录。不要只留平均值。 |
| `results/figures/` | 保存由原始数据生成的图表。图上标明指标、单位和测试条件。 |
| `profiles/` | 保存性能分析的摘要、关键截图或 trace 的索引，并说明它们支持什么判断。 |
| `source-maps/` | 保存带版本、文件位置和代码依据的推理引擎源码阅读笔记。 |
| `communication/` | 保存通信机制与推理性能的关联分析。只有具备真实多卡环境并完成测试，才记录多卡性能结论。 |

新增文件时放到最相关的目录，并从本 README 或项目根目录的日记链接过去。大体积 trace 可以记录存放位置，不必直接加入 Git。

## 目前进度

目前已有目录骨架和本机硬件快照；**还没有在这个目录形成可复现的模型服务基线、性能分析或优化结果**。目录存在不代表对应实验已经完成。现阶段先学习 Python、Git 和调试，再按[总路线图](../LLM-Inference-GPU-Systems-Roadmap-2026-2028.html)逐步开展实验。每日真实成果和待验证事项记录在[学习日记](../日记/README.md)。

开始第一项实验时，先在这里补上实际运行命令、依赖版本、模型与负载、预期输出和原始结果链接，让另一位读者能够照着重跑。
